# Lexi Study

Создай минимально работающую, но уже практически полезную личную web-версию приложения LECTIO для медленного исследовательского чтения текстов на иностранных языках. Это не лендинг и не визуальный макет: все ключевые действия MVP должны реально работать в браузере. Пользователь один, поэтому НЕ делай регистрацию, аккаунты, платежи, тарифы, onboarding, социальные функции и админку.

ГЛАВНАЯ ИДЕЯ
Пользователь читает текст практически на любом языке, нажимает на отдельное слово либо выделяет произвольный фрагмент прямо во время чтения и получает глубокую структурированную исследовательскую карточку: контекстный перевод, морфология/лемма, грамматика и синтаксис, семантика и оттенки, синонимы и различия, этимология, историко-культурный контекст. Выбранную единицу можно сохранить в персональный словарь вместе с предложением и контекстом. Это инструмент close reading, а не обычный переводчик.

ПРИОРИТЕТ №1 — РЕАЛЬНО РАБОТАЮЩИЙ ЦИКЛ
Library → добавить текст → Reader → tap по слову ИЛИ выделение фразы → Analysis panel → сохранить в Vocabulary → продолжить чтение.

1. БИБЛИОТЕКА
Сделай главный экран «Библиотека». Пользователь может добавить новый текст. Для MVP обязательны два способа: (а) вставить текст вручную через textarea, указав название и язык; (б) импортировать локальный .txt файл. Храни книги и прогресс локально в браузере, чтобы после перезагрузки они не исчезали. Для каждой книги показывай название, язык, процент/позицию чтения и кнопку продолжения. Дай возможность удалить книгу с подтверждением. Добавь одну демонстрационную французскую книгу/фрагмент, чтобы приложение можно было испытать сразу.

2. READER
Reader — главный экран продукта. Он должен быть максимально чистым и удобным для долгого чтения. Центрированная колонка текста, хороший serif-шрифт, комфортная ширина строки, интервалы и поля. Верхняя панель минимальна: назад в библиотеку, название, прогресс, настройки чтения. Настройки: размер шрифта, межстрочный интервал, ширина колонки и светлая/тёмная тема. Сохраняй настройки локально.

Критически важно: текст не должен быть набором кнопок или визуально дробиться. Он должен выглядеть как нормальная книга.

3. ВЫБОР ТЕКСТА
Реализуй два сценария.
A) Короткий tap/click по отдельному слову — определить слово под курсором, автоматически определить окружающее предложение и небольшой контекст и открыть анализ.
B) Обычное browser selection для нескольких слов/предложения — после выделения показать компактное действие «Исследовать»; по нажатию открыть анализ именно выделенного фрагмента.
Это должно работать и мышью на desktop, и touch selection на мобильном насколько позволяет браузер. Не ломай нативное выделение текста.

4. ANALYSIS PANEL
На desktop — правая боковая панель или аккуратный overlay; на мобильном — bottom sheet/full-screen sheet. Всегда показывай выбранный фрагмент и исходное предложение. Разделы карточки:
• «Перевод» — буквальный и контекстный;
• «Форма» — lemma, часть речи, морфология;
• «Грамматика» — грамматическая роль/конструкция и синтаксис;
• «Значение» — значение именно здесь и смысловые оттенки;
• «Синонимы» — несколько близких слов и чем они отличаются;
• «Этимология» — происхождение и историческое развитие слова, с явной оговоркой при неуверенности;
• «Контекст» — исторический, культурный, литературный, философский или предметный контекст, только если релевантен;
• «Примеры» — 2–3 полезных примера;
• «Спросить глубже» — поле свободного вопроса по выбранному фрагменту и контексту.
Сделай sections collapsible, чтобы карточка не превращалась в стену текста.

5. AI ДЛЯ MVP
Если в текущем окружении Lovable можно безопасно подключить встроенную AI/LLM-функцию без пользовательского API-ключа — подключи её и сделай настоящий анализ. Если это невозможно без отдельного секрета/платного внешнего API, НЕ блокируй приложение: создай хорошо спроектированный AI service layer и качественный DEMO MODE. Demo mode должен давать полноценный заранее подготовленный глубокий анализ для нескольких слов/фраз демонстрационного французского текста и разумный явно помеченный демонстрационный ответ для остальных selections. В интерфейсе должно быть честно видно «Демо-анализ», если реальный AI не подключён. Никаких фальшивых утверждений, будто запрос реально обработан AI.

6. ПЕРСОНАЛЬНЫЙ СЛОВАРЬ
Кнопка «Сохранить» в анализе. Vocabulary хранится локально. Карточка сохранённой единицы содержит: selection, lemma если есть, контекстный перевод, язык, исходное предложение, название книги, дату добавления. Не допускай бессмысленных дублей: если то же слово/фраза сохранено снова, обнови/объедини запись либо сообщи, что оно уже сохранено. Сделай поиск по словарю и фильтр по языку/книге. Можно удалить запись.

7. ИСТОРИЯ ИССЛЕДОВАНИЙ
Минимально сохраняй последние исследованные selections, чтобы пользователь мог вернуться к ним. Достаточно небольшого списка последних элементов; не усложняй архитектуру.

8. UX / ВИЗУАЛ
Название продукта: LECTIO. Подзаголовок можно использовать «Close Reading». Интерфейс на русском. Эстетика: серьёзная, академичная, интеллектуальная, спокойная; современная типографика + книжный serif для reader. Никаких кислотных градиентов, огромных hero-блоков, маркетинговых карточек, эмодзи, игрового дизайна и визуальной перегрузки. Это должна быть рабочая среда читателя/филолога. Светлая тема — тёплая бумага/слоновая кость, тёмная — глубокий графит, не абсолютный чёрный. Акцент сдержанный. Полностью responsive, особенно под Android-телефон.

9. СОСТОЯНИЕ И ДАННЫЕ
Для этого личного MVP используй local persistence: книги, настройки, словарь, история, позиция чтения. Не добавляй Supabase и авторизацию, если они не нужны для выполнения перечисленного. Приложение должно переживать reload.

10. КАЧЕСТВО
После реализации самостоятельно пройди основной пользовательский сценарий и исправь очевидные ошибки: добавить текст, открыть, нажать слово, выделить фразу, открыть анализ, сохранить, увидеть в словаре, вернуться к книге, reload и убедиться, что данные сохранились. Не оставляй неработающие кнопки, если они выглядят функциональными. Если какая-то функция MVP технически недоступна, явно пометь её в UI вместо имитации.

11. НЕ ДЕЛАТЬ СЕЙЧАС
Не добавляй регистрацию, подписки, оплату, социальные функции, облачную синхронизацию, Anki, сложный SRS, PDF/OCR, EPUB, TTS, speech recognition, gamification, achievement system, marketplace, публичные профили. Это последующие версии.

12. АРХИТЕКТУРНЫЙ ЗАПАС
Хотя MVP локальный, организуй приложение так, чтобы позднее можно было без полной переделки добавить реальный AI backend, EPUB, упражнения/SRS, TTS, морфологические движки, синтаксическое дерево, параллельные переводы и исследовательский режим для древнегреческого/латыни/иврита.

Главный критерий готовности: я открываю приложение на телефоне или компьютере, добавляю иностранный текст, читаю его как книгу, нажимаю слово или выделяю фразу, получаю удобный структурированный анализ, сохраняю интересное в словарь и продолжаю чтение. Сначала обеспечь именно это, затем полируй дизайн.
